# 🧩 Puzzle Programming Language

**Version:** `0.1.3`

**Puzzle** 是一门正在设计与实现中的通用编程语言，目标是在提供**清晰、可组合的抽象能力**的同时，保持**可预测的性能模型**，并最终
**直接编译为高效的原生二进制程序**。

> 把复杂问题拆解成可以拼合的“拼图”，这是 Puzzle 的名字来源，也是它的核心设计理念。

---

## ✨ 语言特性（设计目标）

Puzzle 试图在**表达力、可读性与工程可控性**之间取得平衡，融合多种现代语言设计思想。

## CLI 命令行工具用法

构建项目

```shell
puzzle build --path=<project-path> --features=all --infos=all --exports=all
```

查看版本信息

```shell
puzzle version
```

查看帮助文档

```shell
puzzle help
```

## 项目模块

* **puzzle-cli**

  提供命令行界面，是编译器/工具链对外的入口。负责解析命令参数、接收输入文件、触发编译流程以及输出结果。它依赖其他模块来完成实际的编译过程，但本身不包含语义分析或代码生成逻辑。


* **puzzle-driver**

  编译驱动层，负责组织编译流程的各个阶段（如 frontend → sema → ir → export）。它是 CLI 与内部编译阶段的桥梁，管理不同阶段的顺序、错误传播以及阶段间的上下文传递。


* **puzzle-frontend**

  语言前端部分，负责源代码的词法分析和语法分析，生成完整的抽象语法树（AST）。它还可能负责基本的语法错误检测和初始语义准备。


* **puzzle-sema**

  语义分析器，处理类型检查、作用域解析、符号解析、泛型推断等语义规则。这个模块保证 AST 不仅是语法正确的结构，而且符合语言的语义约束。


* **puzzle-backup**

  备份/快照模块，用于在各个阶段存储中间状态，例如自动保存 AST、IR 或构建快照，以便在错误恢复、调试或增量构建时使用。


* **puzzle-diagnostic**

  诊断和错误处理模块，负责收集、格式化并报告错误、警告以及其他诊断信息。它规范了错误输出格式、位置标注和可视化提示。


* **puzzle-builtin**

  内建类型和内建符号模块，定义语言内置类型（如 Int、Boolean）、标准函数和关键标识符。这个模块在编译早期初始化时被引入到符号表中。


* **puzzle-export**

  导出模块，负责将编译器内部结构（如 AST、IR、依赖图等）序列化为可消费的格式（例如 JSON、YAML、Graphviz/DOT
  等）。它让可视化、调试和工具链扩展成为可能。


* **puzzle-core**

  核心抽象层，定义所有模块共用的基础类型、接口和通用约定。通常包括上下文管理、错误基类、通用数据结构等，是整个编译器架构的血液。


* **puzzle-config**

  配置管理模块，处理编译选项、工程设置、插件配置等。它可以从文件（如 TOML/JSON/YAML）读取配置并将其规范化为内部可用的结构。


* **puzzle-token**

  词法单元定义与处理模块，封装词法分析产生的 Token 类型、分类、位置属性等。它支持前端扫描器输出的基本语素结构。


* **puzzle-ast**

  抽象语法树定义模块，包含所有 AST 节点类型、树结构逻辑及相关访问/遍历接口。其他模块通过这个定义来构建、分析和转换 AST。


* **puzzle-symbol**

  符号定义与管理模块，负责定义符号表的结构、作用域规则、名称解析等。它是语义分析的重要支柱，用来链接声明和引用。


* **puzzle-ir**

  中间表示（IR）模块，定义用于优化和后端生成的通用中间代码结构。它把 AST/语义信息转换成更接近目标代码的形式，并支持各类分析与变换。

## 🧠 编程模型与声明体系

Puzzle 提供统一、强表达力的声明系统，**所有声明均支持在类内部嵌套声明**。

### 支持的声明类型

* **`class` 类**

    * 支持普通类、抽象类
    * 支持继承、多态
    * 支持次构造函数（Secondary Constructor / `ctor`）
    * 支持 `init` 对象初始化块

* **`fun` 函数**

    * 支持普通函数、成员函数、顶级函数
    * 支持 **多返回值（Multiple Return Values）**
    * 支持 lambda 表达式

* **`object` 单例对象**

    * 语言级单例定义
    * 支持 **带参数的单例**
    * 使用 `init ObjectName(args...)` 显式初始化
    * 使用 `init? ObjectName(args...)` 进行安全初始化（若已初始化则跳过）

* **`trait` 特征**

    * 行为抽象单位
    * 支持方法与属性声明
    * 可被类或 object 实现

* **`error` 错误**

    * 错误类型
    * 支持 `match` 获取异常
    * 支持 `|:` 忽略异常，类似: `?:` 的用法

* **`mixin` 混入**

    * 用于代码复用
    * 不参与继承层级
    * 可组合多个 mixin

* **`struct` 结构体**

    * 值语义数据结构
    * 适合轻量级数据建模

* **`enum` 枚举**

    * 支持具名枚举值
    * 可附加属性与行为

* **`annotation` 注解**

    * 编译期与语义分析期元信息
    * 可用于类型、函数、属性等声明

* **`extension` 扩展**

    * 支持扩展函数
    * 支持扩展属性
    * 支持为类型扩展特征

* **`typealias` 类型别名**

    * 提供类型语义别名
    * 支持泛型类型别名
    * 支持类型约束与类型安全隔离

## 👋 变量系统（Variable System）

* **普通赋值**

```puzzle
val name = getName()    // 不可变变量
var age = getAge()      // 可变变量
age++
```

* **支持解构变量**

```puzzle
val [name, age] = getInfo()                     // 强制解构
val [_, age: Int] = getInfo()                   // 支持匿名绑定
var [name: String, val age: Int] = getInfo()    // 支持默认可变性，并单独为属性设置类型和可变性
```

## 🧩 属性系统（Property System）

Puzzle 将属性视为一等语言结构，而非语法糖。

### 属性类型

* **普通属性**

* **延迟初始化属性**

    * `late var`：延迟初始化的可变属性
    * `lazy val`：惰性求值的不可变属性

* **计算属性**

    * 无存储，仅通过表达式计算

* **属性访问器**

    * 自定义 `get`
    * 自定义 `set`

## 🧬 泛型系统（Generics）

Puzzle 提供功能完整且偏向**静态可验证**的泛型系统。

### 泛型能力

* 支持泛型类型与泛型函数
* 支持 **多个 bound**
* 支持协变 / 逆变

    * `out T`
    * `in T`
* 支持 **默认泛型参数**
* 支持 **泛型展开（Variadic Generics）**

    * `T...`
* 支持 **reified（真泛型）**

    * 泛型信息在编译期与运行期均可感知

## 🧭 Context 上下文系统

Context 是 Puzzle 的核心抽象之一，用于表达**隐式依赖、作用域语义与执行环境**。

### Context 可应用于

* **函数**
* **属性**（必须为非普通属性）
* **类**
* **object 单例**
* **trait**
* **mixin**
* **次构造函数**
* **lambda 表达式**

📌 Context 用于：

* 隐式参数传递
* 作用域能力约束
* DSL 构建
* 语义环境注入
